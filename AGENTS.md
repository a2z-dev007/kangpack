# Development & Coding Rules

## 1. Git Workflow & Review Policy (STRICT)
- **DO NOT PUSH TO GIT AUTOMATICALLY**:
  - Never run `git push` on any branch after completing a task or code modification.
  - The user will always review the code changes first.
  - Only push code if the user explicitly instructs: "push the code", "git push", or gives direct permission to push.
- **Commits**:
  - Keep commits clean and localized if committing, but leave pushing strictly to the user's explicit request.

## 2. Code Quality & Verification
- Test and verify changes locally (e.g., compile/build check) before presenting them.
- Provide a clear, concise summary of all modified/created files after completing a task so the user can easily review the diff.
